Supplier bank-change approval

Adapted from the PayeeShield workflow prototype. ATG evaluates registered synthetic authority and verification fixtures, then signs one exact change for a local simulated destination.

This is an approval-control demonstration, not operational fraud protection. No real human is authenticated here. Fixture checks do not establish account ownership.

Demo policy: above £10,000 requires manual review and cannot execute; above £40,000 is blocked. These are illustrative thresholds, not a calibrated fraud score.

Input changes discard the browser’s approval handle. The server separately checks exact signed request and destination version. REVIEW, BLOCK and unknown authority cannot execute.

One shared process-local destination per server; all tabs share it. No durable restart recovery or multi-worker budget is added by this adapter. Never reset real held state. Restarting this demo starts a new fictional run.

Security and trust boundary
Fictional data is sent from this page to the local Node process on 127.0.0.1. No external provider is queried. Decisions use public fixture signing keys and a fixed test clock. Local simulated records are neither encrypted nor independently authenticated destination evidence. No production assurance, certification, real dual-human authentication, fraud detection or bank-account correctness is claimed.
The loopback token and origin checks reduce unintended browser requests; they do not isolate code running as the same OS user. No PayPal checkout or commercial purchase is part of this demo.
