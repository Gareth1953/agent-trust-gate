Deployment containment risk assessment — advisory only.

Codex reported a standalone CLI/SDK prototype (0.1.0-contain.1) with 33/33 assessment tests and two 19/19 clean-install walkthroughs. It evaluates supplied metadata about shared CPU-cache, processor scheduling, storage and service-cache exposure, returning scoped PASS / FAIL / UNKNOWN findings with provenance and confidence.

Not a containment security control: the assessor performs no hardware probing, secret transmission or enforcement. Physical covert-channel detection or prevention remains unproven. Independently isolated credentials, checkpoint custody and complete destination mediation remain blocked. No production certification is claimed.

Explicit threat-model limitation

Agent isolation can leak information through shared resources.

Network separation and file permissions do not alone rule out covert communication through CPU caches, resource contention or shared service state. ATG's bounded local exact-action evaluation does not test or prevent these channels.

ATG-CONTAIN-01 now has a private local metadata-assessment prototype and controlled synthetic fixtures. It does not test physical isolation or establish covert-channel detection or prevention. Dedicated-host arrangements and other mitigations would require independent deployment-specific testing; no general containment guarantee, live protection or certification is implied.

Client information

Start with fictional records.

The public website has no customer-data upload, hosted agent execution API or customer-account system.

Minimise the data

Initial evaluations use synthetic business records. Do not send customer records, personal information, production logs, source secrets, payment details or live credentials by email.

Agree the boundary

Any proposed client-data work needs a separately agreed data flow, permitted processors, access controls, key custody, retention and deletion responsibilities.

Review before deployment

A real deployment needs its own threat assessment, authenticated roles, partner enforcement, incident and recovery procedures, and independent security assessment appropriate to the scope.

Responsible reporting

Report a concern privately.

Email gpmiddleton71@gmail.com with a minimal redacted description, affected version and safe local reproduction. Ordinary email is not a secure secret-transfer channel. Agree a suitable handling route before sharing sensitive evidence.

Please do not post secrets or sensitive exploit details in public issues. Test only local synthetic systems you own or are explicitly authorised to assess. No fixed response or remediation time is promised.

Source review and release status

Maintainer security review is distinct from independent assurance. Source changes and downloadable packages can have different review and release dates. Check the exact version and checksum you evaluate; a source fix does not automatically update a published archive.
