What the integration does

Two safeguards, different responsibilities.

NVIDIA OpenShell: the agent's network route

A real OpenShell 0.1.8 sandbox allowed the test workload to reach one specified destination. A separate, reachable decoy destination was blocked by the runtime's policy.

OpenShell's native TCP policy controlled destination, port and binary access. It did not inspect the purchase or record details inside the HTTP request.

Agent Trust Gate: the exact action

ATG's protected broker read the actual request, checked its signed authority, refused altered or repeated requests and recorded one authorised synthetic change with a lookup receipt.

A separate test mode required an additional passkey assertion, with missing or forged approval refused. These assertions used a software test authenticator, not a real person's device.

Observed results · 12 November 2026

The tests passed. The limits remain visible.

Changed details blocked

Changes to supplier, amount and other exact-action fields, plus forged or expired authority, were rejected before the protected effect.

One effect, no replay

Two concurrent requests resulted in one synthetic commit and one refusal. Reusing the authority was blocked; lookup located the recorded result.

Failure did not trigger a retry

When the broker was unavailable, the workload returned UNKNOWN rather than automatically trying another route or repeating the action.

Evidence: real OpenShell runtime recheck · passkey-required validation · 1,740 regression tests and custody checks. These are internal scoped tests, not independent security assessment.
