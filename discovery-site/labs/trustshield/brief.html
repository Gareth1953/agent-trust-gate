What is actually connected?

The offline harness calls existing ATG canonical action/digest helpers, adds a separately labelled non-production signed binding, then reuses S6 ephemeral signing, authority, SQLite destination and witness mechanisms. It never calls the nonce-consuming ATG verifier as distributed authority and issues no production GatePass. The browser displays the captured harness evidence; it does not run that backend.

What the evidence means

One local destination transaction binds eligible security state, synthetic approval validity/revocation, one-use consumption, manifest state and durable outcome evidence. Witness intent and final checkpoint are separate commits; uncertain gaps require reconciliation. A manifest promotion is not a deployment or proof that software ran.

What it cannot currently protect

  • Compromised hosts, local key owners, colluding authorities or dishonest signed classifications.
  • Coherent rollback of local stores or S6's uncheckpointed revocation-only restore gap.
  • Real destinations or alternate API/console/service-account paths that do not enforce the gate.
  • Unknown vulnerabilities, all malware, zero days, Linux/PHP vulnerabilities or internet outages.

How this compares with existing tools

Identity systems establish principals and access; scanners provide findings; signature/admission tools control supported deployment paths; policy gateways constrain tool calls; approval/audit systems provide governance and logs. Those products overlap substantially. The candidate ATG contribution is an inspectable exact-approval/current-state/destination-outcome chain for one workflow. Its incremental commercial value remains unverified; no first or unique claim is made.

Buyer FAQ

Is TrustShield production-integrated into ATG?

No. S9 is an isolated demonstration adapter using existing pure ATG helpers and synthetic research components. Current plugin/API, banking fixtures and Entra boundaries are unchanged.

Does a valid signature mean software is safe?

No. It attributes a claim and protects its integrity under a trusted key. The producer may be wrong, compromised or missing relevant intelligence.

Can my existing stack already do this?

Possibly. Compare the same exact-action, revocation-race, bypass and reconciliation criteria with your current IAM, gateway and admission tools before funding integration.

What would credible future enforcement require?

Separately authenticated independent authorities, complete destination mediation, conditional commits and revocation fencing, durable consumption, independent rollback witnesses, key custody, availability/recovery operations and external review.

How can I evaluate the evidence?

Use the self-service explorer first. Reproduction uses Node 24.21.0 and existing repository dependencies, offline, without modifying package manifests. The accompanying reproducibility guide identifies exact commands and historical failures.
