One authority core

Two ways to evaluate. One synthetic execution example.

Choose the integration route that fits your local evaluation. Installation alone does not enforce a real external action.

Node.js SDK

Submit the existing v2 business-policy request. Receive a decision and opaque session handle. Changed requests and edited returned decisions cannot create synthetic execution authority.

Local MCP

Start the stdio server with a host-selected absolute state path. Exactly one tool, atg.evaluate_action, is exposed. No execution or administration tool.

Gated synthetic example

Only an enforced ACCEPT can reach the built-in synthetic adapter. Shadow, referral, refusal, expiry and reuse are blocked. Decision and synthetic execution receipts remain separate and linked.

Host-controlled evaluation

Keep authority explicit.

  • Use synthetic data; do not provide production credentials or customer data.
  • Keep the absolute state path outside the installed package.
  • Run one process per state file; no distributed or cross-process locking guarantee.
  • Session handles do not survive restart; lifecycle and exposure records do.
  • No automatic retry after uncertain execution.

Learning and execution verification

Learning remains possible future advisory work: anomaly detection and human-reviewed suggestions. It must not expand authority or rewrite enforcement.

External execution verification, including a possible Salmon connection, is exploratory. No integration or partnership is implemented.

Technical partners and buyer evaluations

Bring one bounded agent workflow.

A live partner adapter would need exact-action enforcement, bypass prevention, real authority records, trusted time, protected keys and external-effect reconciliation. The current package does not establish those production properties.
