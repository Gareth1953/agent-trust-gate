Exact Action Trust Gateway for AI agents.

Agent Trust Gate™ checks whether an AI agent’s exact proposed action remains within a human-authorised mandate at the point where action authority would be granted. It returns deterministic evidence and, only where permitted, a tightly bound one-use GatePass.

ATG does not decide whether an action is commercially wise, beneficial or correct. It verifies declared authority, exact-action integrity, policy conditions and lifecycle state.

The point-of-action gap

Legitimate instructions can still become a changed action.

An agent may start with a valid task and later propose a different supplier, quantity, price, account, destination, resource or timing. Model confidence does not create authority.

The ATG question

Does the evidence authorise this agent to perform this exact action, here and now, within these limits?

Verify authority before AI acts. No verified standing. No current authority. No exact-action proof. No valid GatePass. No action.

One coherent architecture

Integrate, decide, assure.

The three layers share the same exact-action authority core. The integration boundary does not create authority; the trust gate does not execute; assurance artefacts do not become permission.

Layer 1

Agent Integration Gateway

Protocol-compatible MCP stdio operation using version 2025-06-18. Only atg.evaluate_action is exposed. There are no MCP execution, policy-administration, revocation or emergency-control tools.

Layer 2

Exact Action Trust Gateway

Checks registered tool/schema identity, agent standing, human mandate, policy, freshness and lifecycle state. GatePass remains exact-action-bound, expiring, revocable and one-use.

Layer 3

Business Assurance & Customer Trust

Adds buyer policy contracts, deterministic risk tiers, Shadow Mode, aggregate exposure, emergency stop, recovery, Customer Trust Receipts and an evidence-backed Coverage Map.

How ATG works

Deterministic controls before permission.

All current public scenarios are local and synthetic. One frozen in-process synthetic adapter can acknowledge one permitted demonstration action; it makes no real order or payment.

01

Mandate

A human defines bounded authority and evidence requirements.

02

Propose

The agent submits one exact canonical action.

03

Evaluate

Standing, mandate, policy, evidence and lifecycle checks run.

04

Verdict

ACCEPT, REJECT, REFER, or revocation prevents progression.

05

Evidence

Decision and any synthetic execution receipt remain separate.

ACCEPTAll mandatory checks pass; enforced mode may issue a one-use GatePass.
REJECTThe action is invalid, prohibited, altered, unauthorised or unverifiable.
REFERNo authority is granted; human review or additional evidence is required.
REVOKEInternal lifecycle control invalidates unconsumed authority; it does not reverse execution.

Shadow Mode: runs the same proposed-verdict path but issues no GatePass, mutates no enforcement state and grants no execution authority.

P3-M162 Customer Trust Evidence

Verify evidence without turning it into authority.

Customer Trust Receipts are digest-bound summaries derived from verified local evidence. They are non-authorising and cannot reserve, execute, retry, revoke or act as GatePasses. Decision and execution receipts remain separate.

  • Tampered, missing, substituted or mismatched evidence fails verification.
  • The verifier checks canonical bundle content and locked source evidence.
  • Reviewer-readable Markdown and machine-readable JSON derive from the same evidence.
  • Evidence says what was demonstrated and keeps absences visible.

Safety and trust boundaries

What the evidence does not establish.

No production deployment, payment execution, security certification, customer data, live employee directory or production key custody is claimed.

Local and synthetic

Synthetic/minimised data and opaque references only. No production secrets, live procurement, payment, settlement or customer communication.

Not production infrastructure

No production IAM or key custody, distributed durability guarantee, high availability or real external-effect reconciliation.

No outcome guarantee

No customer adoption or validation, regulatory approval, guaranteed compliance, guaranteed safety, proven ROI, fraud/loss reduction, statistical significance or business-outcome correctness.

Execution boundaryNo autonomous capital execution. No automatic retry after an uncertain execution state. The buyer retains control of any real execution boundary.
