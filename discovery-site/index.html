The control problem

AI capability is not authority.

An agent may know what to do, have access to a tool and produce a confident answer — yet still lack authority for a specific supplier, amount, account, customer outcome or high-impact action. ATG concentrates on that point-of-action gap.

A

Identity is not standing

A declared software identity is not enough. ATG demonstrates how control of an agent identity, an accountable principal and current delegation can be checked before normal GatePass evaluation.

Open Agent Standing demo →
H

Approval is not authority

An approved: true field does not prove that an authorised person sanctioned the exact action. ATG links human identity, organisational authority and action-specific approval evidence.

Open Human Authority demo →
G

Permission must match the action

GatePass binds proof to one canonical action with freshness and one-use controls. Changed actions, replay, expiry and unresolved proof states are designed to fail closed in the demonstrator.

Integration advantage

Use the authority evidence you already trust.

Agent Trust Gate™ is designed to complement existing identity, authority and approval infrastructure rather than replace it. A future organisation-specific integration can treat suitable trusted evidence as input, then ATG asks the narrower question that matters at the point of action.

Does this evidence authorise this agent to perform this exact action, here and now, within these limits?

  • Keep existing IAM, identity, authentication and approval systems upstream.
  • Bring trusted identity, standing, mandate, delegation or approval evidence into the decision.
  • ATG checks whether that evidence is sufficient for the exact proposed AI action.
  • PASS produces an action-bound GatePass; insufficient or untrusted evidence produces a recorded refusal.
  • Decision evidence remains separate from any later execution evidence.
No rip-and-replace requirement

Trusted authority evidence → ATG exact-action verification → signed GatePass or recorded refusal.

ATG does not need to become another enterprise identity directory, authentication platform or universal credential issuer. Existing systems can establish upstream facts; ATG determines whether those facts authorise the exact action now being proposed.

Current boundary: the public demonstrator uses deterministic synthetic/local evidence only. It does not currently connect to live IAM, SSO, identity-provider, enterprise-directory, external credential or production approval systems.

Trust architecture

From requester to accountable evidence.

ATG separates several facts that are too often collapsed into a single “allowed” result. Each layer answers a different trust question before the action can proceed.

Layer 01

Standing

Layer 02

Layer 03

Human-understandable proof

Technical trust should become understandable evidence.

GatePass, Human Authority Proof, Agent Standing and execution evidence are technical structures. The direction is to make those structures capable of producing a simple trust receipt that an accountable person can understand without losing the underlying proof.

  • What exact action was proposed?
  • Which agent requested it and under whose delegation?
  • Which authority and evidence were checked?
  • Which human approved it, when policy required one?
  • Was the action allowed, refused or left unexecuted?
Core principle

No verified standing. No current authority. No exact-action proof. No valid GatePass. No action.

ATG is designed to put the trust decision before the consequential action — then preserve evidence of what the gate decided and what subsequently happened.
