The buyer question

Can this exact action proceed under this exact authority?

An agent can be authenticated and still propose the wrong amount, supplier, account, scope or timing. The controlled pilot tests the trust boundary immediately before a consequential action without connecting ATG to a live execution system.

Step 01

Buyer test inputs

Synthetic or approved test action, authority, mandate, policy and agent-standing evidence.

Step 02

ATG verifies

Canonical action, authority, standing, limits, policy, freshness, signatures and replay state.

Step 03

PASS or REFUSE

ATG issues a GatePass only for a fully allowed action, otherwise a recorded refusal.

Step 04

Buyer retains control

The buyer owns every real execution decision and system. The default pilot performs no live action.

Three core scenarios

Prove that the gate can allow — and refuse.

The pilot uses deterministic, bounded scenarios so business, security and control owners can inspect both successful and refused outcomes.

1

Valid authorised action

An approved human and recognised agent propose an action inside the agreed amount, scope and time. Expected result: PASS, one-use GatePass, Trust Receipt and full audit receipt.

2

Authority or mandate violation

Overspend, wrong authority, expiry or out-of-scope action. Expected result: REFUSE with an intelligible root cause, refusal evidence and no valid GatePass.

3

Adversarial or replay attempt

Change the action after approval, alter a bound value or reuse a consumed GatePass. Expected result: invalid execution authority with tamper or replay evidence.

What the buyer receives

Decision evidence that can be reviewed later.

  • PASS or REFUSE with structured reason evidence
  • Canonical exact-action digest
  • One-use GatePass only when the complete request is allowed
  • Human Authority Proof and Agent Standing evidence references
  • Human-readable executive Trust Receipt
  • Full machine-readable audit receipt
  • Reproducible scenario and test results
Safe pilot boundary

Buyer-controlled test inputs → ATG PASS / REFUSE + evidence → buyer retains execution control.

The default pilot is decision-and-evidence only. No buyer execution system is connected. ATG does not create a real order, payment or external action.

Pilot safety

Keep production risk outside the evaluation.

The controlled pilot is deliberately narrow. It is intended to establish whether the control adds value before any separate production engineering or assurance programme is considered.

Synthetic or approved test data

No production credentials, payment tokens, bank details, live customer data or live execution endpoints are permitted in the standard pilot.

Fail-closed stop conditions

The pilot stops for an authority bypass, inconsistent decision, exact-action binding failure, replay failure, unexplained receipt mismatch or need for live money movement.

Clear ownership

The buyer remains authoritative for identity, permissions, policy, legal/compliance approval, test data, environment and any downstream execution.
